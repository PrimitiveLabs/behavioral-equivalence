# Human observation and timing policy

Status: pilot findings and revised design, not a confirmatory freeze.

Official source: https://raw.githubusercontent.com/chongminggao/KuaiRand/main/README.md . The `is_click` field is interface dependent: a click in the two-column UI and a valid-play criterion in the single-column UI. Initial reports must call this the recorded click/valid-play outcome and stratify by supported interface/scenario labels. Mapping the 15 `tab` values to interface types still requires evidence.

The initial 1K preparation found 11,756,073 source rows. Excluding all repeated user timestamps left only 158,971 rows. That output is a diagnostic artifact and is unsuitable as the primary behavioral benchmark. Do not train or claim primary fidelity from `prepared-v2`.

Revision v3 preserves timestamp ties as unordered bundles. All predictions within one user/timestamp bundle receive the same strictly preceding observable history. No within-bundle sort creates a causal ordering. Chronological boundaries operate on bundle positions, so a timestamp group never crosses splits. User-disjoint splits preserve every user's group assignment. Event-level targets stay separate for scoring; inference and bootstrap account for user dependence.

History may include a bundle only after its outcomes become observable. The provisional conservative availability timestamp adds nonnegative play, profile-stay and comment-stay durations to `time_ms`. This is an assumption about log semantics, not proven by a column name. Confirm it against the source documentation and test sensitivity to additional embargo before preregistration. Until then, model fits are timing-assumption pilots only. Never use current-bundle outcome values, realized watch times, or monthly aggregates as prediction inputs.

The cloud v3 pilot deduplicates identical records on its retained field set. The full benchmark must use complete source-record fingerprints, retain a duplication sensitivity analysis, and document the absence of unique event identifiers. The full source archive remains unchanged on Modal. Randomized exposure flags are recorded outcomes of assignment, not generic permission to claim arbitrary environmental interventions.

Pilot isolation for 27K: the releases reindex identities, so matching numeric user IDs is insufficient. Build a bijective release-to-release map using full per-user timestamp/scenario multisets from the unfiltered source logs, without outcome labels or video IDs. Require unique fingerprints and an exact multiset match, then exclude all matched pilot users from confirmatory evaluation. If an unambiguous full mapping cannot be established, obtain an independent confirmatory source or holdout whose separation can be proved. Do not assume separate archives imply independent users.

Current revision v4 retains all 19 official source columns and deduplicates only identical complete source records. It retains 11,661,848 interactions, including 43,027 randomized exposures, across the same 2,032,217 timestamp bundles. The independent v4 audit covers every retained row and all 1,000 users. The model pilots use v4. Revision v3 and the heavily filtered v2 output remain diagnostic history, with their limitations recorded; neither replaces the full-record primary pipeline.

The full candidate 27K pipeline preserves both max-per-record and summed-within-bundle duration proxies. If tied records represent sequential activity sharing a coarse timestamp, the maximum proxy alone need not cover the bundle's observation duration. Neither proxy proves availability from the published column definitions. Evaluate an additional prespecified embargo before the final model freeze, and state the resulting timing assumption in every human result. Keep the primary outcome named recorded click/valid-play; the absence of a published tab-to-UI mapping does not justify silently treating every tab as a click interface.

The candidate pipeline partitions raw logs into 32 user buckets on Modal, constructs outcome-free identity fingerprints from all raw records, excludes matched pilot users, then performs full-record deduplication and timestamp-bundle splits. An independent integration test runs in the pinned cloud data image. Complete conversion, the 1,000-user identity match, the 26,285-user remaining cohort and an independent full-data split audit are still required before confirmatory fitting.
